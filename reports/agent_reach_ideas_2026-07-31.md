# Agent-Reach — Идеи для Hermes (2026-07-31)

> Репозиторий: `Panniantong/Agent-Reach` (Trendshift #1, MIT).
> Концепция: Единая CLI/SKILL-обёртка над готовыми open-source CLI/MCP инструментами для чтения контента с платформ.

## Главные идеи под наш стек

1. **Фасад над готовым софтом (CLI Wrapper Pattern)**:
   - Не писать свои парсеры с нуля, а оборачивать узкоспециализированные утилиты: `yt-dlp` (YouTube), `bili-cli` (Bilibili), `twitter-cli` (X), `feedparser` (RSS), `jina-ai/reader` (Web -> Markdown).
   - Единый интерфейс диагностики (`agent-reach doctor`) для проверки доступности платформенных каналов.

2. **Jina Reader как простой веб-скрейпер без селениума**:
   - `curl https://r.jina.ai/URL` даёт чистый Markdown любой страницы без тяжелого headless-браузера.

3. **Fallback-цепочки доступности (Resilient Route)**:
   - Авто-переключение источника при блокировке (пример: Bilibili заблокировал yt-dlp -> переключились на bili-cli).

4. **Локальное хранение кук**:
   - Куки не уходят на внешние сервисы, берутся локально из браузерного профиля/Cookie-Editor.

---

## Что НЕ брать в Hermes
- Автоматические системные инсталлеры с курлом по скриптам без `шиф`.
- Токены / абуз схемы.
