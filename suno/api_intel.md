# Suno API Intelligence

> Source: paperfoot/suno-cli `API_INTELLIGENCE.md` (reverse-engineered April 2026, verified live 2026-07-18)
> Status: confirmed endpoints — reference for understanding Suno's request/response cycle directly.

## Base URL

```
https://studio-api-prod.suno.com
```

## Auth

- **Clerk-based**: browser has Clerk session cookies → exchanges for JWT
- JWT used as `Authorization: Bearer <jwt>`
- **JWT lifetime**: ~1 hour. Auto-refreshed by Clerk SDK in browser.
- Clerk session ID in JWT `sid` claim (e.g. `session_eece6e4f36131cbcb12aeb`)

### Required headers

```
authorization: Bearer <jwt>
device-id: <from-browser-persisted>
browser-token: {"token":"<base64-encoded>"}
origin: https://suno.com
referer: https://suno.com/
```

### Auth strategies

1. **Cookie-based** (recommended): store Clerk session cookies, auto-refresh JWT via `auth.suno.com/v1/client/sessions/<sid>/tokens`
2. **Direct JWT**: user pastes JWT, works ~1 hour, then expires

## Verified Endpoints

### GET /api/billing/info/
Full account info: credits, plan, models, features, limits.

### POST /api/c/check
**Captcha preflight** (verified 2026-07-18).

Request: `{"ctype": "generation"}` with Bearer JWT.
Response: `{"required": false, "captcha_version": 1}`

`required: false` for accounts above Suno's trust threshold → solver can be skipped.

### POST /api/generate/v2-web/
**Main generation endpoint.**

Payload:
```json
{
  "make_instrumental": false,
  "mv": "chirp-fenix",
  "prompt": "",
  "generation_type": "TEXT",
  "continue_at": null,
  "continue_clip_id": null,
  "metadata": {
    "web_client_pathname": "/create",
    "create_mode": "custom",
    "create_session_token": ""
  },
  "token": "",
  "tags": "pop, upbeat, synths",
  "title": "Summer Vibes",
  "negative_tags": "metal, heavy, dark"
}
```

**IMPORTANT**: `token` field = hCaptcha token when required. Do NOT send `token_provider` field — 422s. Only `token` rides on request body.

**Two modes**:
1. **Description mode**: `metadata.create_mode = "inspiration"`, `prompt` = description → Suno writes lyrics
2. **Custom mode**: `metadata.create_mode = "custom"`, `prompt` = lyrics, `tags` + `title` + `negative_tags` set

Response: `{"clips": [...], "metadata": {...}, "status": "..."}`

### POST /api/generate/lyrics/
**Free lyrics generation** (no captcha, just JWT auth).

Request: `{"prompt": "description of song"}`
Response: `{"id": "<uuid>"}` (async — poll for result)

### GET /api/generate/lyrics/{id}
Response when complete:
```json
{
  "text": "[Verse 1]\n...\n[Chorus]\n...",
  "title": "Generated Title",
  "status": "complete",
  "error_message": "",
  "tags": ["style description auto-generated by Suno"]
}
```

### POST /api/generate/concat/v2/
Concatenate/extend clips.
Request: `{"clip_id": "<id>"}`

### POST /api/feed/v3
List user's clips.

Request: `{"cursor": "", "limit": 20, "filters": {...}}`
Omit `cursor` for first page. Page numbers NOT accepted.

Response: `{"clips": [...], "next_cursor": "...", "has_more": true}`

Clip structure includes: `id`, `title`, `status`, `model_name`, `audio_url`, `audio_url_2`, `video_url`, `image_url`, `metadata` (tags, prompt, duration, avg_bpm, has_stem, is_mumble, is_remix, make_instrumental, type, can_remix, priority, stream, uses_latest_model).

### POST /api/edit/stems/{clip_id}
**Stem separation** — correct path (NOT `/generate/stems/`).

### POST /api/cover/
Cover generation with different style/model.

### POST /api/remaster/
Remaster with different model version.

### GET /api/playlist/me
User playlists.

### GET /api/trending/
Trending clips.

## Persona / Voice Creation Flow

6-step pipeline (captured April 2026):

### Step 1: Upload voice sample
S3 presigned upload → `POST /api/uploads/audio/{upload_id}/upload-finish/`
Response: `200 OK` (empty body)

### Step 2: Poll upload status
`GET /api/uploads/audio/{upload_id}/`
Response: JSON with processing status.

### Step 3: Extract vocal stem
`POST /api/processed_clip/voice-vox-stem`
Body likely: `{"upload_id": "<id>"}`. Extracts clean vocals from uploaded audio.

### Step 4: Record verification phrase
User reads: *"Listening to the melody of a gentle summer breeze"*
Second upload goes through same upload-finish flow with new upload_id.

### Step 5: Voice verification
`POST /api/voice-verification/`
Verifies voice matches. Body includes both upload IDs + verification text.

### Step 6: Create persona
`POST /api/persona/create/`
Creates voice persona from verified audio clips. Large payload (~47KB — likely base64 audio).

## Key Insights

1. **Captcha is the main challenge** — generation requires hCaptcha token for non-trusted accounts
2. **Lyrics generation is free** — no captcha, just JWT auth
3. **Captcha preflight** (`/api/c/check`) tells you if solver needed before wasting a generation
4. **JWT refresh** — Clerk cookie exchange or session keepalive
5. **browser-token** — dynamically generated from timestamp, base64-encoded
6. **Stems endpoint** — `/api/edit/stems/{clip_id}` not `/generate/stems/`
